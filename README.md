# عافية | Afiyah

منصة عربية للجوال لتنظيم متابعة صحة أفراد الأسرة، بملفات مستقلة باسم المريض ومشاركة محددة لكل ملف.

الموقع: https://almohammdin.github.io/afiyah/

## حالة الإصدار 1.0

الواجهة والتجربة التفاعلية جاهزتان. **الدخول الحقيقي وبيانات المرضى السحابية معطلان عمدا إلى حين ربط Firebase والتحقق من قواعد الوصول.** زر استكشاف يشغل بيانات اصطناعية في الذاكرة فقط. تغلق أو تحدث الصفحة فتزول؛ لا تستخدمه لحفظ معلومات طبية حقيقية.

الوظائف المنفذة:
- واجهة RTL متجاوبة وهوية عافية وخطوط Thmanyah Sans وThmanyah Serif Display وEl Messiri من مرجع الهوية الذي قدمه صاحب المشروع.
- ملفات مرضى، أدوية ووقت جرعة وتسجيل الأخذ اليومي، مواعيد ومناطق زمنية السعودية/دبي، مهام ومسؤول متابعة، وملاحظات تقارير.
- بحث وتعديل وحذف، ملخص متابعة محسوب من السجلات، وتصدير ICS بتذكير قبل 30 دقيقة. العنوان عام لحماية الخصوصية في التقويم، والمكان المدخل يصدّر.
- تكامل Firebase Auth Google وFirestore مهيأ في الكود، غير موصول حاليا.
- نموذج مشاركة بالبريد: دعوة معلقة ثم قبول، اطلاع أو تحرير أو صلاحيات على مستوى الأقسام، وإلغاء الوصول.
- سجلات تحديثات من التطبيق. ليست سجلات تدقيق مقاومة للتلاعب: العميل يمكنه إنشاء إدخال سجل ضمن صلاحياته؛ يلزم خلفية موثوقة إذا أصبحت مطلوبة لهذا الغرض.

## قرارات النطاق

- أي شخص يمكنه التسجيل بحسابه في Google بعد الربط. ألغيت موافقة مدير التفعيل بناء على آخر طلب.
- المريض لا يحتاج حسابا. الحساب يخص الشخص الذي يدخل، والملف باسم المريض؛ كل مشارك يستخدم هويته الخاصة.
- صاحب الملف يدير المشاركة؛ لا توجد صلاحية مدير عامة للاطلاع على الملفات.
- كل مشارك يرى معلومات الملف الأساسية (الاسم والعلاقة وسنة الميلاد وفصيلة الدم). التحكم التفصيلي يشمل الأدوية والمواعيد والمهام والتقارير، وليس إخفاء حقول داخل سجل واحد.
- روابط الموقع لا تحتوي بيانات المريض. لا مشاركة عامة للملفات ولا وضع صحي دون اتصال. Firestore يستخدم ذاكرة مؤقتة في RAM فقط، وAuth يستخدم session persistence.
- الخدمة تبدأ بميزانية صفرية. لا تفعيل فوترة أو تخزين أو ذكاء اصطناعي خارجي.
- رفع PDF والصور غير مفعل. Firebase Storage يتطلب Blaze حاليا. لا يتم تحويل الملفات إلى base64 للتحايل على قيود التخزين.
- ملخص المتابعة حسابي، وليس نموذج ذكاء اصطناعي. لم ينفذ وكيل حجز أو إرسال بريد/SMS/WhatsApp أو push عند إغلاق الموقع.
- تعيين مسؤول في المهمة حقل تنظيم فقط، ولا ينشئ دعوة أو يرسل رسالة.
- الجرعات اليومية: سجل مستقل لكل وقت، يعتمد يوم الجهاز المحلي. الجداول الطبية المعقدة وتغيير المنطقة أثناء السفر خارج هذا الإصدار.
- سحب المشاركة يمنع الطلبات اللاحقة من الخادم. لا يسترجع ما سبق نسخه أو عرضه. عرض البيانات يتحدث عند فتح/تحديث الصفحة؛ ليس تزامنا فوريا.

## استكمال Firebase لاحقا

1. إنشاء مشروع مستقل لعافية بحساب المالك على خطة Spark. لا تعاد استخدام مشاريع جزرة أو مسراح أو قواعدها.
2. اختيار منطقة Firestore بعد اعتماد مكان البيانات من المالك؛ لم يحسم مكان التخزين بعد.
3. تفعيل Google في Authentication وإضافة `almohammdin.github.io` إلى Authorized domains.
4. إنشاء تطبيق Web ونسخ إعداداته العامة إلى `config.js` مع بقاء `enabled: false` حتى اكتمال الاختبارات. لا تضع service account أو access token في المستودع العام.
5. نشر `firestore.rules` و`firestore.indexes.json` للمشروع المحدد:
   ```sh
   firebase deploy --only firestore:rules,firestore:indexes --project YOUR_DEDICATED_PROJECT_ID
   ```
6. اختبار القواعد في Emulator أو بيئة مستقلة قبل بيانات حقيقية: مالك/قارئ/محرر/حساب غريب/بريد غير موثق/دعوة معلقة/دعوة مسحوبة. يجب أن تفشل محاولات التصعيد، القراءة المباشرة عبر API، وتعديل عضوية ملف آخر.
7. ضبط `config.enabled = true` بعد نجاح ذلك، واختبار الدخول والخروج ومشاركة ملف بين حسابين على نطاق GitHub Pages.
8. التحقق من النسخ الاحتياطي والتصدير والحذف قبل الاعتماد لحفظ سجلات أصلية. لا توجد حاليا خدمة نسخ احتياطي تلقائية.

`firestore.rules` جاهزة للمراجعة والاختبار، ولم تنشر أو تختبر ضد Firebase حي. اختبارات هذا المستودع تتحقق من نموذج البيانات التجريبي والواجهة فقط، ولا تثبت أمان بيئة إنتاج غير موجودة.

## التطوير والتحقق

```sh
npm ci
npm test
npm run check
```

الموقع ملفات ثابتة في جذر المستودع ولا يحتاج بناء. يحمّل Firebase SDK المثبت على 11.10.0 فقط عند تفعيل الربط. انشر جذر `main` عبر GitHub Pages. الخطوط والأصول محفوظة محليا داخل المستودع؛ حافظ على تراخيص المصادر. الصور PNG مقدمة من المالك وليست ملفات vector.
